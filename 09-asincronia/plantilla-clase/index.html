1 · Síncrono vs asíncrono y el event loop

    

      JavaScript tiene un solo hilo: hace una cosa cada vez. Aun así puede
      atender temporizadores, animaciones y peticiones de red sin congelarse. El truco tiene
      nombre: event loop.
    


    

      La analogía de la fila del banco. Código síncrono es una única
      caja atendiendo: hasta que el cliente de delante no termina, nadie avanza. Código
      asíncrono es esa misma caja, pero cuando un trámite necesita esperar (una firma
      del director, por ejemplo) el cajero le da un número al cliente, lo manda a la sala de
      espera y sigue atendiendo. Cuando la firma llega, avisan al cliente y vuelve a la caja.

2 · Callbacks y el callback hell

    

      Un callback es simplemente una función que le pasamos a otra función para
      que la llame cuando termine su trabajo. Fue la primera forma de escribir código asíncrono
      en JavaScript... y también la primera fuente de dolor de cabeza.
    


    

      Analogía: dejas tu número de teléfono en el taller mecánico. No te quedas
      allí de pie mirando; te vas a hacer otras cosas y ellos te llaman cuando el coche está
      listo. Tu número de teléfono es el callback.

3 · Promesas: estados, encadenado y combinadores

    

      Una promesa es un objeto que representa un valor que todavía no existe, pero que
      existirá (o fallará) en el futuro. Tiene exactamente tres estados y solo puede cambiar de
      estado una vez.
    


    

      Los tres estados:
      pending (pendiente, aún trabajando) →
      fulfilled (cumplida, hay un valor) o
      rejected (rechazada, hay un error). Una promesa cumplida o rechazada se dice
      que está settled (resuelta, en el sentido de "ya no cambiará").

4 · async / await

    

      async/await no sustituye a las promesas: es una forma de escribirlas
      que se lee como código normal, de arriba abajo. Por dentro sigue habiendo promesas.
    


    

      Dos reglas que hay que memorizar.
      1) Una función async SIEMPRE devuelve una promesa, aunque su
      return sea un número. 2) await solo puede usarse dentro de una
      función async (o en el nivel superior de un módulo ES).
    


    

      
      
      
    


    
4.1 · Secuencial vs paralelo (con cronómetro)

    

      Tres tareas de 600 ms cada una. Si las esperamos de una en una dentro de un bucle,
      tardaremos unos 1800 ms. Si las lanzamos a la vez con Promise.all, unos
      600 ms. Esta es la optimización más rentable del día.

5 · fetch: hablar con un servidor

    

      fetch() lanza una petición HTTP y devuelve una promesa que se cumple con un
      objeto Response. Leer el cuerpo de esa respuesta (response.json())
      es una SEGUNDA promesa. Por eso siempre hay dos esperas.
    


    

      ⚠️ El error número uno con fetch: un 404 o un 500 no rechazan la
      promesa. Para fetch, "el servidor respondió" ya es un éxito, aunque la
      respuesta sea un error. Solo se rechaza si la red falla del todo. Por eso hay que
      comprobar response.ok a mano y lanzar el error nosotros.
    


    

      
      
      
    


    
5.1 · Cancelar una petición con AbortController

    

      Si el usuario cambia de pantalla mientras se descargan datos, seguir esperando es tirar
      batería y ancho de banda. AbortController nos da un mando a distancia para
      cancelar.

6 · Proyecto práctico: lista de usuarios

    

      Juntamos todo: pedimos usuarios a una API real, mostramos un spinner mientras llegan,
      pintamos tarjetas cuando llegan, enseñamos una pantalla de error si algo falla y una
      pantalla de "sin resultados" si el filtro no encuentra nada.
    


    

      Este ejemplo funciona SIEMPRE, incluso sin internet. La función
      obtenerUsuarios() intenta primero un fetch real a
      jsonplaceholder.typicode.com. Si falla por lo que sea (sin conexión, archivo
      abierto con file://, API caída), captura el error y devuelve un array de datos
      simulados tras un retraso artificial. La insignia de abajo indica de dónde vienen los datos
      que estás viendo.
